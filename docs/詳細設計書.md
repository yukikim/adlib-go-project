## 4. 認証・認可詳細設計

### 4.1 認証方式

- メールアドレス + パスワード認証
- セッションベースまたは JWT ベースを採用候補とする
- パスワードはハッシュ化して保存する

### 4.2 認可方式

- role によりアクセス可否を制御する
  - guest
  - member
  - admin

### 4.3 パスワード再設定

- 再設定トークンを発行する
- メールリンク経由で再設定画面へ遷移させる
- トークンには有効期限を持たせる

## 5. sessionSet 詳細設計

### 5.1 入力データ

- SessionEvent
- SessionEntry
- Participant
- ParticipantSongRequest

### 5.2 通常生成詳細

- round1 の曲を候補曲とする
- drum / bass / piano は必須とする
- 希望者を優先する
- 上限に達した参加者は候補から除外する
- vocal 参加時は front を 1 名までに制御する

### 5.3 sessionSetForce 詳細

- 未生成曲のうち希望者不足のみ対象とする
- requesterCount の多い順で処理する
- 不足必須パートは以下で選ぶ
  - 参加上限未満
  - 参加曲数が最少
  - 同率ならランダム

### 5.4 出力データ

- sessionSets
- forcedSessionSets
- skippedSongs

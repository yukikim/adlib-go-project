# Adolib-go KICK-OFF 基本設計書

## 1. 文書概要

本書は、Adolib-go KICK-OFF の基本設計を簡易的に整理したものです。

要件定義書:

- docs/要件定義書.md

## 2. システム全体像

本システムは、以下 3 つの領域で構成する。

- 公開サイト領域
- メンバーサイト領域
- 管理サイト領域

既存の sessionSet 生成機能は管理サイト領域の中核機能として組み込む。

## 3. 想定アーキテクチャ

### 3.1 採用技術

- フロントエンド: Next.js App Router
- サーバサイド API: Next.js Route Handlers
- ORM: Prisma
- DB: PostgreSQL
- 認証: 将来的に NextAuth 系または同等の認証基盤を想定
- メール送信: Node.js からメール送信ライブラリを利用

### 3.2 レイヤ構成

- Presentation Layer
  - 公開ページ
  - メンバーページ
  - 管理ダッシュボード
- Application Layer
  - 認証
  - セッションエントリー処理
  - sessionSet 生成処理
  - 通知処理
- Domain Layer
  - 参加者
  - セッション
  - sessionSet
  - チャット
  - お知らせ
- Infrastructure Layer
  - PostgreSQL
  - Prisma Client
  - メール送信

## 7. sessionSet 機能の基本設計

### 7.1 通常生成

- round 1 希望を基点に候補曲を抽出する
- drum, bass, piano を優先割り当てする
- vocal は希望曲のみ参加させる
- front は最大 2 名、vocal 参加時は 1 名に制限する
- 参加曲数が少ない人を優先する

### 7.2 強制追加生成

- 通常生成で落ちた曲のうち、希望者不足が理由のものを再処理する
- 他の希望者数が多い曲から優先する
- 不足パートは、参加曲数が最少の候補者群からランダム選出する
- 強制追加された楽器情報を保持する

### 7.3 生成結果表示

- 生成された sessionSet 一覧を表示する
- 強制追加生成された曲一覧を表示する
- 未生成曲と理由を表示する

## 9. 権限設計方針

### 9.1 権限区分

- 未ログインユーザー
- ログインメンバー
- 管理者

### 9.2 権限制御

- 公開ページは未ログインでも閲覧可能
- メンバー機能はログイン必須
- 管理機能は管理者権限必須
- sessionSet 編集、公開、メール送信は管理者のみ可能

## 10. 運用設計方針

- セッション募集開始時に案内メールを送信する
- エントリー締切後に Round2 を開始する
- sessionSet は管理者確認後に公開する
- メール送信履歴と重要な操作履歴は保存する

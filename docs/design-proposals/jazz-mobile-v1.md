# Adlib Go Jazz Mobile Concept 01

トップページ、公開ページ、メンバーマイページを対象にした、モバイルファーストのデザイン検討案です。現在の画面は変更せず、独立したプレビュールートとして追加しています。

## プレビュー

- トップ: `/design-preview`
- 公開ページ: `/design-preview/public`
- メンバーマイページ: `/design-preview/member`

表示内容はレイアウト検討用のサンプルです。実際のイベント、コラム、メンバー情報には接続していません。

## デザイン方針

### Jazz の表現

- 夜の会場を思わせる Ink Black
- サックスや照明を連想させる Brass Gold
- 古い譜面のような Warm Paper
- 録音中のランプを思わせる Muted Red
- レコードの溝、五線譜、セットリストをCSSと文字組みで表現

写真を主役にせず、Jazzらしい「間」「反復」「ずれ」を余白、罫線、非対称グリッドで表しています。

### モバイルファースト

- 主要操作は高さ48px以上
- 重要情報は1カラムで上から順に理解できる構成
- メンバーページは「次に必要な行動」を最上部に固定
- 補足情報はネイティブの `details` / `summary` で段階表示
- メンバーページのみ、親指で届きやすい下部ナビゲーションを採用
- `md` / `lg` 以上で情報量を増やし、横並びへ展開

## 軽量化の考え方

- 外部画像なし
- 新しいWebフォントなし
- JavaScriptによるアニメーションなし
- 3ページともReact Server Component
- 装飾はCSS gradientとborderが中心
- アイコンライブラリに依存せず、文字とCSSで意味を表現
- 共通ヘッダー、見出し、ボタン、ステータスを1ファイルに集約

実装に移す際も、ファーストビューに大きな背景画像を置かず、イベント画像が必要なコラムだけ `next/image` で遅延読み込みする構成を推奨します。

## ページ別の情報設計

### トップ

1. ブランドメッセージ
2. 次回イベント
3. 参加までの3ステップ
4. 最新コラム
5. メンバーマイページへの導線

現在の複数ボタンやクイックリンクを整理し、初見の利用者が「どんなコミュニティか」「次はいつか」「どう参加するか」を短時間で理解できる順序にしています。

### 公開ページ

コラム一覧とAboutページに展開できる編集的なレイアウトです。カードを大量に並べず、タイトル、要約、発行日を主役にしています。後半に次回イベントのプログラムを置き、読み物から参加案内へ自然につなげます。

### メンバーマイページ

既存機能を次の3層に整理しています。

1. 今すぐ必要な操作: 参加可否、リクエスト曲、締切
2. 次回イベントの確認: 開催概要、参加状況、公開sessionSet
3. 後から使う機能: 履歴、アーカイブ、プロフィール、管理者への連絡

イベントの状態ごとに色の違う大きなカードを並べるのではなく、重要度と期限で表示順を決めます。公開sessionSetやアーカイブなどの状態は、小さなステータスラベルで表現します。

## Next.jsでのコンポーネント展開

今回の共通部品は `src/components/design-preview/JazzPreviewShell.tsx` にまとめています。本実装時は次の粒度へ分割できます。

```text
src/components/public/
  SiteHeader.tsx
  Hero.tsx
  UpcomingEventCard.tsx
  StoryList.tsx

src/components/portal/
  MemberSummary.tsx
  NextActionCard.tsx
  MemberEventCard.tsx
  PublishedSetList.tsx
  MemberQuickLinks.tsx

src/components/shared/
  SectionHeading.tsx
  StatusBadge.tsx
  ActionLink.tsx
```

データ接続時は、見た目の部品にPrismaやfetchを直接持たせず、既存の `PublicHomePage` と `useMemberPortal` が取得した値をpropsで渡します。これにより、デザイン変更と認証・イベント処理を分離できます。

## 本実装へ移す場合の順序

1. 色、文字サイズ、角の有無をデザイントークンとして確定
2. 共通ヘッダーと見出し部品を置き換え
3. トップページを実データへ接続
4. 公開コラム一覧・詳細を同じトーンへ統一
5. メンバーページで「次の行動」を算出する表示用データを追加
6. 既存フォーム、ダイアログ、アーカイブを新しいカード内へ移植
7. 実機幅、キーボード操作、コントラスト、読み込み速度を確認

本実装では既存の認証、エントリー、レイティング、アーカイブ処理を維持し、まず表示コンポーネントだけを段階的に差し替えるのが安全です。

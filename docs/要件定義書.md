# Adolib-go KICK-OFF 要件定義書

## 1. 文書概要

本書は、既存の sessionSet 生成アプリをベースとして、コミュニティサイト機能を持つ Web アプリケーション Adolib-go KICK-OFF に拡張するための簡易要件定義をまとめたものです。

元資料:

- ../プロジェクト拡張計画.md

対象は以下の 2 系統です。

- 既存の sessionSet 生成機能の継続利用
- メンバーサイト、管理機能、コミュニケーション機能の追加

## 2. システム目的

- セッション主催者の運営業務を効率化する
- メンバー同士の継続的なコミュニケーション基盤を提供する
- セッション告知、参加募集、曲希望、sessionSet 作成を一元管理する

## 3. 想定利用者

### 3.1 メンバー

- セッション参加者
- 楽器演奏者および vocal

### 3.2 管理者

- セッション主催者
- メンバー管理、告知、sessionSet 作成、公開を担当する運営者

## 4. 機能要件

### 4.1 公開ページ機能

- トップページを表示できる
- コラム一覧ページを表示できる
- コラム詳細ページを表示できる
- adolib-go について の紹介ページを表示できる

### 4.2 メンバー認証機能

- メンバー登録ができる
- サインインができる
- サインアウトができる
- パスワード再設定ができる
- パスワード再設定時にメール送信ができる

### 4.3 メンバー情報管理機能

- 以下の項目でメンバー登録できる
  - 名前
  - メールアドレス
  - メイン楽器
  - サブ楽器
  - 性別
  - 年代
  - 住処
  - パスワード
- Drum, Bass, Piano, Vocal 以外の楽器は Front 扱いにできる
- メンバーはプロフィールを編集できる
- メンバーはニックネームを設定できる
- メンバーは自己紹介文を設定できる

### 4.4 マイページ機能

- 自分のプロフィールを確認できる
- 自分のプロフィールを編集できる
- 管理者からのお知らせを確認できる
- 現在のセッション参加状況を確認できる
- 過去のセッション履歴を確認できる

### 4.5 メンバー間コミュニケーション機能

- ログインメンバーは他メンバー一覧を閲覧できる
- ログインメンバーは他メンバーのプロフィールを閲覧できる
- 1 対 1 チャットができる
- 1 対 1 チャット投稿時に相手へメール通知できる
- グループチャットができる

### 4.6 セッションエントリー機能

- ログインメンバーはセッション参加可否を登録できる
- Round1 エントリーでリクエスト曲 2 曲を登録できる
- エントリー可能期間を設定できる
- エントリー期間終了後に Round2 エントリーを開始できる
- リクエスト曲なしの参加登録にも対応できる

### 4.7 sessionSet 機能

- セッションエントリー結果を元に sessionSet を生成できる
- 既存の sessionSet 生成ロジックを活用できる
- 管理者は生成された sessionSet を編集できる
- sessionSet をメンバー向けに公開できる
- sessionSet を PDF ダウンロードできる
- セッション当日にログインメンバーは sessionSet から任意のセットへレイティングできる
- レイティングは星 1 から 5 で登録できる
- 管理者は sessionSet に対するメンバーのレイティングを随時集計できる
- 管理者は sessionSet の編集前後を問わず、実施情報とレイティングを含むアーカイブを保存できる
- アーカイブは過去 3 年分を保存し、管理者は適時削除できる

### 4.8 管理者機能

- 管理者認証ができる
- 管理者ダッシュボードを利用できる
- 既存 app/page.tsx 相当の管理 UI をダッシュボードに統合できる
- メンバー一覧を確認できる
- メンバープロフィールを確認、編集できる
- メンバー削除ができる
- メンバーアクティビティ履歴を確認できる
- 1 対 1 チャット履歴を確認できる
- セッションエントリーページ設定ができる
  - 実施日
  - 場所
  - 時間
  - 告知文
  - 募集期間
- セッション公開時に全メンバーへ案内メールを送信できる
- 任意メンバーまたは全員へお知らせメールを送信できる

## 5. 非機能要件

- Web ブラウザで利用できること
- メンバー認証情報を安全に管理できること
- メール送信機能を実装できること
- sessionSet 生成結果を再現性ある形で管理できること
- 管理者向け機能とメンバー向け機能を権限で分離できること

## 6. 前提・制約

- 現在の Next.js + Prisma + PostgreSQL 構成を継続利用する
- 既存の sessionSet 生成 API を中核ロジックとして活用する
- 将来的にメンバーサイトへ拡張するが、現時点では一部要件は未詳細化である
- チャット機能は当初は静的またはシンプルな構成で開始する

## 7. 今後の要件詳細化ポイント

- メンバー権限と管理者権限の厳密な境界
- セッション開催単位のデータ構造
- コラム機能の運用フロー
- チャットの既読、通知、保持期間
- PDF 出力形式
- メール送信基盤の選定
- レイティング入力期限と再評価可否
- アーカイブ削除時の監査ルール
